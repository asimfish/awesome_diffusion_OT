# cuRegOT: A GPU-Accelerated Solver for Entropic-Regularized Optimal Transport

> Yixuan Qiu · arXiv 2026 · [arXiv](https://arxiv.org/abs/2605.08793) · 证据级 [R] · 课题 T29 高性能 OT 求解器与训练基础设施
> **一句话**：把 SPLR 拟牛顿法 GPU 化，用摊销符号分析、CPU/GPU 异步候选迭代与融合梯度 kernel，在 η=0.001 难例上快于 Sinkhorn 系 GPU 求解器。

## 1. 问题

离散 OT 的精确 LP 求解在 $n\approx m$ 时复杂度为 $O(n^3\log n)$（Sec. 1），熵正则化（Cuturi, 2013）把问题变成光滑无约束对偶优化，Sinkhorn 算法成为事实标准，且天然适合 GPU 并行。但作者指出，Sinkhorn 在困难问题上收敛慢（Abstract；Sec. 1）。

近期出现的 Newton 型方法——SNS（Tang et al., 2024）、SSNS（Tang and Qiu, 2024）、SPLR（Wang and Qiu, 2025）——在收敛速度上优于 Sinkhorn，但 GPU 化受阻：Newton 步需要求解大型稀疏线性系统，而稀疏 Cholesky 分解的符号分析（symbolic analysis）与重排序本质上是串行过程，难以在 SIMT 架构上并行，导致现有实现要么停留在 CPU，要么 GPU 利用率严重不足（Abstract；Sec. 1；Sec. 3.2）。本文要解决的就是这个「二阶 OT 方法上 GPU」的工程与算法瓶颈。

## 2. 方法

cuRegOT 基于 SPLR 算法（Wang and Qiu, 2025）。SPLR 求解对偶问题（4）$\min_{x\in\mathbb{R}^{n+m-1}} f(x)$，用拟牛顿方向 $x^+ = x - \gamma B^{-1}g$，其中 $B$ 是 Hessian 的近似：

$$B = H_\Omega + (\xi uu^T + \zeta vv^T) + \tau I \tag{5}$$

$H_\Omega$ 是稀疏化的 Hessian（只保留索引集 $\Omega$ 中的 $T_{ij}$ 项），rank-two 项继承 BFGS 规则，$\tau I$ 是对角正则。稀疏化方案 $\Omega$ 用 top-k 规则：选 $T$ 中最大的 $k$ 个元素，其余置零（Sec. 3.1）。步长 $\gamma$ 由满足 Wolfe 条件的线搜索确定（Eq. 8）。

cuRegOT 在 SPLR 之上加了三项 GPU 针对性设计（Sec. 4.1）：

1. **摊销符号分析（amortized symbolic analysis）**：每 $S$ 次迭代（实验取 $S=10$）才做一次 CPU 上的符号分析与重排序，中间 $S-1$ 次迭代复用既有稀疏模式，只更新非零元素的数值。作者观察到 top-k 稀疏模式在迭代间演化缓慢（Sec. 4.2；附录 A.2 有图示）。

2. **CPU/GPU 协作候选迭代生成**：当 CPU 在做符号分析时，GPU 上异步触发一个 CUDA stream，跑若干次轻量 Sinkhorn 迭代生成候选解 $x^s_k$；CPU 完成后 GPU 再算拟牛顿候选 $x^q_k$，两者比较目标函数值，选更优者作为 $x_k$（Sec. 4.3）。图 2 的 profiling 显示该机制把原本的 GPU 空闲窗口填上了 Sinkhorn 迭代。

3. **融合梯度 kernel**：把 $T_{ij}=\exp\{(\alpha_i+\beta_j-M_{ij})/\eta\}$ 的元素计算、行归约（$\nabla_\alpha f = T\mathbf{1}_m - a$）和列归约（$\nabla_{\beta_{-m}} f = T_{-m}^T\mathbf{1}_n - b_{-m}$）合并成单次遍历。线程块大小为 $32\times D$（$D=8$），行归约用 warp shuffle（`__shfl_down_sync()`）在寄存器内完成，列归约用共享内存原子加。每个 $M_{ij}$ 只从全局内存读一次（Sec. 4.4）。

## 3. 理论结果

**定理 4.1**（重述 Wang and Qiu, 2025 的 Corollary 3.4）：对任意满足 $\Omega \supseteq \Omega^*$ 的稀疏化方案，稀疏化 Hessian 满足

$$0 < \lambda_{\min}(H) \le \lambda_{\min}(H_\Omega) \le \lambda_{\max}(H_\Omega) \le \lambda_{\max}(H)$$

即稀疏化不扩大特征值范围，条件数始终被 $\lambda_{\max}(H)/\lambda_{\min}(H)$ 控制。这是摊销符号分析安全性的依据（Sec. 4.2）。

**定理 5.1**（全局收敛）：设 $\{x_k\}$ 由修改后的算法生成——非 $iS$ 次迭代用标准 SPLR 步，$k=iS$ 次迭代在拟牛顿候选 $x^q_k$ 与任意点 $x^s_k$ 之间取目标函数值更小者。则 $\lim_{k\to\infty}\|\nabla f(x_k)\|=0$，即全局收敛到最优解（Sec. 5.2）。

**定理 5.2**（线性收敛率）：同定理 5.1 设置下，存在常数 $0<r<1$ 使得对所有 $k\ge 1$，

$$f(x_k) - f^* \le r\,[f(x_{k-1}) - f^*]$$

其中 $r$ 的表达式在附录 B.3，依赖于问题参数 $(M, a, b, \eta, x_0)$（Sec. 5.2）。

**复杂度分析**：融合梯度 kernel 中 $T$ 矩阵元素计算为 $O(nm/K)$（$K$ 为 GPU 线程数），行归约 $O(5nm/K)$，全局内存写 $O(g_c nm/K)$，列归约 $O(mn/K)$，共享内存写 $O(Dm/(32g_c))$，全局内存写 $O(g_r m/(32g_c))$（Table 1；$g_r\times g_c$ 为 block 网格尺寸）。

## 4. 实验与数字

**设置**：成本矩阵按最大值归一化 $M \leftarrow M/\max_{i,j}M_{ij}$；主实验固定 $\eta=0.001$；所有求解器收敛容差设为零，跑固定迭代数（10, 20, 50, 100 等）画误差-时间曲线；每配置预热后重复 10 次，报告运行时间与优化误差的中位数；误差度量是边际误差 $\text{Error}=\|T\mathbf{1}_m-a\|_1+\|T^T\mathbf{1}_n-b\|_1$（Sec. 6.1）。

**基线**：POT-GPU（Sinkhorn、Greenkhorn）、OTT-JAX（Sinkhorn、Anderson 加速版，memory size=5）、CuPy 实现的 AccSinkhorn（Lin et al., 2022）、cuRegOT（SPLR）。Greenkhorn 因收敛几乎平坦被从图中剔除（Sec. 6.1；Sec. 6.4）。

**数据集**：
- Synthetic I：Gaussian 点云，平方欧氏距离成本；iid 变体（源目标均 $N(0,1)$）与 diff 变体（源 $N(0,1)$，目标 $N(1,0.25)$）；尺寸 $(n,m)=(1600,1200),(3200,2400),(6400,4800)$。
- Synthetic II：指数分布（均值 1）到双峰 Gaussian 混合（$0.2\cdot N(1,0.04)+0.8\cdot N(3,0.25)$），在 $[0,5]$ 上均匀网格离散化，平方欧氏成本。
- CIFAR-10：两类各 5000 张图，$n=m=5000$；用预训练 ResNet-18 提取深度特征后算平方欧氏距离（Sec. 6.2–6.3）。

**关键数字**（从图 3、图 4 读取，原文未给表格化数值）：

| 数据集 | 尺寸 | 观察 |
|---|---|---|
| Synthetic I (iid) | 1600×1200 | cuRegOT 在约 0.1s 内达到边际误差 $10^{-8}$ 量级，Sinkhorn 系在 0.5s 时仍在 $10^{-2}$–$10^{-4}$ 区间（Fig. 3a 左） |
| Synthetic I (iid) | 6400×4800 | cuRegOT 约 1s 内达 $10^{-8}$，AccSinkhorn 约 8s 时误差约 $10^{-3}$（Fig. 3a 右） |
| Synthetic I (diff) | 6400×4800 | cuRegOT 约 1s 达 $10^{-8}$，其余方法在 2.5s 内未低于 $10^{-2}$（Fig. 3b 右） |
| Synthetic II | 6400×4800 | Anderson 加速版比标准 Sinkhorn 更慢；cuRegOT 约 2s 达 $10^{-8}$，其余在 8s 时约 $10^{-2}$–$10^{-4}$（Fig. 3c 右） |
| CIFAR-10 (0 vs 1) | 5000×5000 | cuRegOT 约 1s 达 $10^{-8}$，Sinkhorn 系在 8s 时约 $10^{-2}$–$10^{-3}$（Fig. 4 左上） |

作者报告：cuRegOT 在几乎所有案例中收敛更快，尤其在高精度区间；问题尺寸越大优势越大（Sec. 6.4）。原文未给出具体 speedup 倍数。

**消融**（Fig. 5，尺寸 6400×4800 与 5000×5000）：去掉摊销符号分析（-A）、去掉 Sinkhorn 候选生成（-S）、两者都去掉（-A-S）均使求解变慢，说明两个组件都有贡献（Sec. 6.5）。原文未给定量差距。

## 5. 在 OT×扩散地图中的位置

cuRegOT 属于「第二代→第三代」过渡线上的工作：它把 2025 年的二阶方法 SPLR（Wang and Qiu, 2025，ICML 2025）从 CPU 搬到 GPU，补齐了「难例小 $\eta$」象限的 GPU 求解能力。在方法谱系上：

- **继承**：SPLR（Wang and Qiu, 2025）的 sparse-plus-low-rank 拟牛顿结构；SNS/SSNS（Tang et al., 2024；Tang and Qiu, 2024）的稀疏二阶思路。
- **竞争**：与 GPU Sinkhorn 系（POT、OTT-JAX、AccSinkhorn）直接竞争；与 PDOT（Lu and Yang, 2024）分属不同精度定位——PDOT 面向无正则 OT 的高精度 LP 解，cuRegOT 面向熵正则 OT 的难例快速收敛。
- **互补**：与 kernel 级 IO 工程（FlashSinkhorn、FastSinkhorn）正交——后者优化 Sinkhorn 的每迭代 IO，cuRegOT 优化二阶方法的每迭代瓶颈。两者针对的是同一张「误差-时间」图的不同算法族。

在扩散/流匹配训练管线中，batch 内 OT 配对的实际开销已被量化（Immiscible Diffusion、Haxholli、Boïté），cuRegOT 提供的价值是：当配对问题本身是难例（小 $\eta$、高精度需求、大 batch）时，二阶 GPU 求解器可以比 Sinkhorn 系更快到达同等边际误差。但本文没有做任何扩散训练端到端实验，也没有与 FlashSinkhorn 类 kernel 方法对比，其「在扩散管线中能省多少」仍是开放问题。

## 6. 局限与批评

**作者承认的**：
- 未来工作包括进一步减少对 host 端符号分析的依赖、探索迭代或混合精度稀疏求解器、扩展到更广的 OT 形式（Sec. 7）。这说明当前实现仍依赖 CPU 做符号分析，只是摊销而非消除。
- 收敛率常数 $r$ 依赖问题参数，表达式放在附录 B.3，正文未给出显式形式（Sec. 5.2）。

**读出来的**：
1. **实验对比范围窄**：基线全是 Sinkhorn 系（POT、OTT-JAX、AccSinkhorn），没有与 PDOT、FlashSinkhorn/FastSinkhorn 或 CPU 版 SPLR 对比。无法判断 cuRegOT 相对「CPU SPLR 的 GPU 加速比」或相对「IO-aware Sinkhorn 在中等 $\eta$ 下的表现」。
2. **固定 $\eta=0.001$ 是刻意选难例**：主实验只测一个正则化强度，$\eta$ 的影响放在附录 A.6（原文截断，未见具体数字）。在较大 $\eta$ 下 Sinkhorn 收敛快，cuRegOT 的二阶开销可能不划算，但正文未讨论这个 crossover。
3. **误差度量是边际误差而非对偶间隙或 transport cost 误差**：作者在附录 A.5 解释了理由（原文截断，未见），但边际误差对某些应用（如需要精确 plan 的配对）可能不是最终关心的量。
4. **单卡、单精度路径**：全文未见多 GPU 或混合精度讨论；稀疏 Cholesky 的数值稳定性在小 $\eta$ 下是否受 fp32 限制未讨论。
5. **预印本证据级 [R]**：所有「显著快于」的结论是作者报告，未经同行评审。

## 7. 对我们的启发

1. **难例配对的求解器选型**：如果我们的扩散/流匹配管线中 batch 内 OT 配对需要小 $\eta$（接近精确指派）或高精度边际满足，cuRegOT 的 SPLR 路线比 Sinkhorn 系更值得试。但要注意：cuRegOT 是 CUDA 专用、依赖稀疏 Cholesky，集成进 PyTorch 训练循环的工程成本高于直接调 POT/OTT-JAX。可先在「配对质量-墙钟时间」基准里加一个 cuRegOT 数据点，验证它在我们的 batch 尺寸（如 8192）和 $\eta$ 设定下是否仍有优势。

2. **CPU/GPU 异步重叠的思路可迁移**：cuRegOT 的「CPU 做串行符号分析时 GPU 跑轻量 Sinkhorn 候选」是一个通用的 latency-hiding 模式。我们的 OT 配对与训练流水线重叠调度（切入点 #4）可以借鉴：dataloader worker 或独立 CUDA stream 上跑配对，与 backward 重叠。cuRegOT 的定理 5.1/5.2 给出了「插入外部候选迭代不破坏收敛」的证明模板，如果我们做异步配对 + 候选选择，可以引用这个论证结构。

3. **融合 kernel 的 row/column 双归约模式**：cuRegOT 的梯度 kernel 用 warp shuffle 做行归约、共享内存原子加做列归约、单次读 $M_{ij}$。这个模式直接适用于任何需要同时算行和列边际的 OT 变体（UOT、partial OT 的梯度也含行/列归约）。如果我们做 unbalanced OT 的 GPU kernel（切入点 #1 的 UOT 方向），可以复用这个 tile 设计和归约分工。
