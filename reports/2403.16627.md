# SDXS: Real-Time One-Step Latent Diffusion Models with Image Conditions

> Yuda Song, Zehao Sun, Xuanwu Yin · arXiv 2024 · [arXiv](https://arxiv.org/abs/2403.16627) · 证据级 [R] · 课题 T30 端侧部署、benchmark 与顶会趋势
> **一句话**：UNet+VAE 双小型化 + 特征匹配/分数蒸馏一步训练，512² 达约 100 FPS，1024² 达约 30 FPS。

## 1. 问题

扩散模型图像生成受制于两个成本来源：模型架构大（U-Net 与 VAE 解码器参数多、计算重）和采样步数多（迭代去噪导致延迟成倍放大）。作者指出，已有工作分别从压缩（pruning、distillation、quantization）和减少 NFE（progressive distillation、consistency distillation、Rectified Flow、GAN-based 方法）两个方向推进，但「同时探索模型小型化与一步化」的工作在文献中很少（Sec. 1）。此外，作者指出一个具体痛点：用 LoRA 把模型微调成少步模型后直接套用原 ControlNet 是次优的，因为 LoRA 更新后的模型中间特征图分布与原模型不同；当微调到一步模型时，低秩更新不够用，全量微调又会让特征分布差异更大，因此需要一种能在一步模型上训练 ControlNet 的方法（Sec. 1）。

## 2. 方法

整体方案分两条轴：架构蒸馏（VAE 解码器、U-Net、ControlNet）和一步训练（feature matching warmup + segmented score distillation）。

**VAE 蒸馏**：用预训练扩散模型采样 latent code $z$，用预训练 VAE 解码器重建图像 $\tilde{x}$，训练一个极小的解码器 $G$，损失为（Eq. 5）：

$$L_{VD} = \|G(z)_{\downarrow 8\times} - \tilde{x}_{\downarrow 8\times}\|_1 + \lambda_{GAN} L_{GAN}(G(z), \tilde{x}, D)$$

其中 $D$ 是 GAN 判别器，L1 损失在 8 倍下采样图像上计算。作者主张用不含 attention 和 normalization 层的精简 CNN 架构，只保留残差块和上采样层（Sec. 3.1）。

**U-Net 蒸馏**：采用 BK-SDM 的 block removal 策略，选择性删除残差块和 Transformer 块，用输出知识蒸馏（OKD）和特征知识蒸馏（FKD）损失训练紧凑模型（Eq. 6–8）：

$$L_{OKD} = \int_0^T \mathbb{E}_{x_0 \sim p_0(x), x_t|x_0 \sim p_t(x_t|x_0)} \|s_\theta(x_t, t) - s_\phi(x_t, t)\|_2^2 dt$$

$$L_{FKD} = \int_0^T \mathbb{E}_{x_0 \sim p_0(x), x_t|x_0 \sim p_t(x_t|x_0)} \sum_l \|f_\theta^l(x_t, t) - f_\phi^l(x_t, t)\|_2^2 dt$$

$$L_{KD} = L_{OKD} + \lambda_F L_{FKD}$$

与 BK-SDM 不同，作者排除了原始去噪损失（Sec. 3.1）。对 SD-2.1 base，删除 middle stage、下采样最后一级、上采样第一级，以及最高分辨率级的 Transformer 块；对 SDXL-1.0 base，删除大部分 Transformer 块（Sec. 3.1）。

**ControlNet 蒸馏**：不直接蒸馏 ControlNet 的 zero convolution 输出，而是把 ControlNet 与 U-Net 合并后蒸馏 U-Net 的中间特征图和输出；特征蒸馏只应用于 U-Net 解码器，因为 ControlNet 不影响 U-Net 编码器的特征图（Sec. 3.1）。

**一步训练**：作者指出，用 ODE 采样器从预训练 DM 构造噪声-图像对来训练一步模型会产生低质量图像，原因是采样轨迹存在交叉（crossings），导致一个噪声输入对应多个可行目标；在 MSE 损失下，模型会输出多个可行解的加权平均，造成模糊（Eq. 9）。作者提出用 feature matching 损失替代 MSE，基于 DISTS 损失在特征图上计算 SSIM（Eq. 10）：

$$L_{FM} = \sum_l w_l \cdot \text{SSIM}(f_\theta^l(x_\theta(\epsilon)), f_\theta^l(\psi(x_\phi(\epsilon))))$$

其中 $x_\theta(\epsilon)$ 是 tiny U-Net 一步生成的图像，$\psi(x_\phi(\epsilon))$ 是原 U-Net 用 ODE 采样器生成的多步图像。作者报告使用预训练 CNN backbone、ViT backbone 和 DM U-Net 编码器都能得到良好结果（Sec. 3.2）。同时，作者用 LCM 等已有微调方法或公开的少步模型来拉直轨迹，缩小可行输出范围。$L_{FM}$ 单独用作 warmup，只用少量训练步数（Sec. 3.2）。

**Segmented Score Distillation**：作者指出 Diff-Instruct 的 score distillation 在 $t \to T$ 时需要加高水平噪声，此时估计的 score 函数不准确；而扩散模型采样轨迹从粗到细，$t \to T$ 时 score 提供低频信息梯度，$t \to 0$ 时提供高频信息梯度。因此把时间步分成两段 $[0, \alpha T]$ 和 $(\alpha T, T]$，后者用 $L_{FM}$ 替代（Eq. 11）：

$$\text{Grad}(\theta) \approx \int_0^{\alpha T} F(t, x_t) dt + \lambda_{FM} \frac{\partial L_{FM}(x_\theta(x_t), \psi(x_\phi(x_t)))}{\partial \theta}$$

其中 $F(t, x_t) = w(t) \mathbb{E}_{x_0 = g_\theta(z), x_t|x_0 \sim p_t(x_t|x_0)} [s_\phi(x_t, t) - s_{p_t}(x_t)] \frac{\partial x_t}{\partial \theta}$（Eq. 12）。训练初期设 $\alpha$ 接近 1、$\lambda_{FM}$ 取高值，概率密度显著重叠后逐步降低两者。online DM 与 student DM 交替训练（Algorithm 1）。训练后，作者发现模型生成图像纹理偏少，因此用 GAN loss 配合极低秩 LoRA 做短期微调，GAN loss 使用 StyleGAN-T 的 Projected GAN loss，基本设置与 ADD 一致（Sec. 4）。

**LoRA 与 ControlNet 训练**：一步 DM 训练完成后，可用 LoRA 配合 Segmented Score Distillation 微调风格。预训练 LoRA 插入 offline DM（若兼容也插入 Teacher DM），不插入 online DM；跳过 feature matching warmup（Sec. 3.2）。ControlNet 训练时，U-Net 参数固定，只训练蒸馏后的 ControlNet；控制图像从 teacher 模型采样的图像中提取（而非数据集图像），以保证噪声、目标图像、控制图像构成配对三元组；原多步 U-Net 的预训练 ControlNet 集成到 online 和 offline U-Net 中但不参与训练，仅作为预训练特征提取器。作者发现将 U-Net 的部分噪声输入替换为重新初始化的噪声可以增强控制能力（Sec. 3.2）。

## 4. 实验与数字

**训练设置**：代码基于 diffusers 库开发。由于无法访问 SD v2.1 base 和 SDXL 的训练数据集，整个训练过程几乎是 data-free 的，只依赖公开数据集（LAION-5B）的 prompt；必要时用开源预训练模型配合 prompt 生成对应图像。训练 mini-batch size 配置为 1,024 到 2,048，必要时用梯度累积。SDXS-1024 训练时用 Vega（SDXL 的紧凑版）作为 online DM 和 offline DM 的初始化（Sec. 4）。

**延迟对比**（Table 1，512×512，batch size=1）：SD v2.1 base 的 U-Net 参数 0.87B、延迟 16 ms、NFE 32，总延迟 532 ms（文本编码器 2.2 + U-Net 512 + 图像解码器 18）；SDXS-512 的 U-Net 参数 0.32B、延迟 6.3 ms、NFE 1，图像解码器参数从 50M 降到 1.2M、延迟从 18 ms 降到 1.7 ms，总延迟 9.1 ms（1.1 + 6.3 + 1.7）。

**延迟对比**（Table 2，1024×1024，batch size=1）：SDXL 的 U-Net 参数 2.56B、延迟 56 ms、NFE 32，总延迟 1868.6 ms（3.6 + 1792 + 73）；SDXS-1024 的 U-Net 参数 0.74B、延迟 24 ms、NFE 1，图像解码器参数 1.2M、延迟 6.1 ms，总延迟 31.9 ms（1.8 + 24 + 6.1）。

作者在 Sec. 4.1 明确说明：由于 FID 的高斯分布假设过强，FID 不是衡量图像质量的好指标，受生成样本多样性影响显著，但按前人惯例仍报告。SDXS-512 的 CLIP Score（32.81）高于 SD v1.5（31.84）和 Tiny SD（31.06）；SDXS-1024 的 CLIP Score（32.32）低于 SDXL（33.77）和 Vega（32.99），高于 SDXL Lightning（32.09）。FID 方面 SDXS-512（28.21）劣于 SD v1.5（24.28）和 SD Turbo（26.50），优于 Tiny SD（31.16）和 SD v1.5-LCM（34.74）；SDXS-1024（30.92）劣于 SDXL（24.60）、SDXL-LCM（28.87）、SDXL Lightning（29.26）和 Vega（29.24）。

**速度声明**：摘要报告 SDXS-512 约 100 FPS（比 SD v1.5 快 30 倍）、SDXS-1024 约 30 FPS（比 SDXL 快 60 倍），在单 GPU 上。Table 3 的实测延迟为 SDXS-512 9 ms（约 111 FPS）、SDXS-1024 32 ms（约 31 FPS）。

**LoRA 实验**：Figure 9 展示两种不同风格 LoRA 的生成样本，风格能有效迁移到 offline DM 的风格，同时大体保持场景布局一致性（Sec. 4.1）。

## 5. 在 OT×扩散地图中的位置

本文位于「少步化 × 模型压缩」的交叉点，属于部署线（T30）中 2024 年的支线工作，与 SnapFusion、MobileDiffusion、EdgeFusion 同期。其与 OT 的接口在 Sec. 3.2 的轨迹交叉分析：作者用「采样轨迹交叉导致一个噪声对应多个目标图像、MSE 下模型输出加权平均而模糊」来解释一步蒸馏的困难，并引用 Rectified Flow 的 reflow 策略作为拉直轨迹的对照方案。作者的实际做法是：用 LCM 等已有微调方法或公开少步模型来「straighten the model's trajectories」，再用 feature matching 损失替代 MSE 来规避交叉带来的模糊——即把轨迹拉直作为预处理，而非训练目标本身。这对应课题背景中「轨迹几何→少步可行性→端侧延迟」因果链的中间环节：本文没有显式度量直线度，也没有用 OT 耦合做配对，但明确承认轨迹交叉是少步化的核心障碍，并用外部拉直手段缓解。

在评测方面，本文对 FID 的批评（Sec. 4.1：「由于高斯分布假设过强，FID 不是衡量图像质量的好指标，受多样性影响显著」）与课题背景中 FID 的 OT 本质（Inception 特征上高斯拟合的 W2 距离）及其对少步模型的系统性偏差直接呼应。作者仍报告 FID 是「按前人惯例」，但已明确标注其局限。

## 6. 局限与批评

**作者承认的**：
1. 训练后模型生成图像纹理偏少，需要额外的 GAN loss + 极低秩 LoRA 短期微调来补救（Sec. 4）。
2. ControlNet 生成图像多样性存在明显局限，换 prompt 可缓解但未解决（Sec. 4.2）。
3. FID 不是衡量图像质量的好指标，受多样性影响显著（Sec. 4.1）——这意味着 Table 3 中 SDXS 的 FID 劣势可能部分源于多样性收缩而非质量下降，但作者未提供替代指标。

**读出来的**：
1. 训练是「几乎 data-free」的，只用 LAION-5B 的 prompt 和开源模型生成的图像，没有使用 SD v2.1 base / SDXL 原始训练数据。这使结果与使用原始数据训练的方法（如 SD Turbo、SDXL Lightning）不可直接公平对比，且生成图像的分布上限受限于 prompt 集和 teacher 模型。
2. 延迟数字的测试条件（float16、batch size=1、模型编译后）在 Table 3 脚注中给出，但摘要中的「100 FPS / 30 FPS」是近似值，且未说明 GPU 型号；Table 1/2 的延迟分解与 Table 3 的总延迟（9 ms vs 9.1 ms；32 ms vs 31.9 ms）存在微小不一致，原文未解释。
3. 一步训练依赖 LCM 或公开少步模型做轨迹拉直，这意味着 SDXS 的一步化质量上限受制于这些外部模型；如果外部少步模型本身有轨迹交叉或质量缺陷，会传导到 SDXS。

## 7. 对我们的启发

1. **「轨迹交叉→MSE 模糊」的论证可迁移到少步×低比特复合误差分析**：本文用 Eq. 9 说明轨迹交叉下 MSE 导致加权平均模糊，这一机制在量化场景下可能加剧——量化噪声会进一步扰动配对关系。可沿课题切入点 #1 设计实验：在 SDXS 类一步模型上施加 {W8A8, W4A8, W4A4} 量化，测量轨迹交叉程度（可用 T09 的直线度 S(Z) 代理）与量化后质量退化的相关性。
2. **feature matching 作为「免配对」蒸馏损失值得在 OT 框架下重新审视**：本文用 SSIM-based feature matching 替代 MSE 来规避轨迹交叉问题，本质上是放弃了逐点配对约束、转向分布级特征匹配。这与 OT 耦合蒸馏（切入点 #3）形成对照：OT 耦合是「重新配对」而非「放弃配对」。可以做一个系统对比：同一 teacher 下，feature matching warmup vs. minibatch-OT 耦合蒸馏 vs. 两者组合，看一步模型的质量与多样性权衡。
3. **ControlNet 蒸馏的「控制图像从 teacher 采样图像提取」策略是数据构造层面的 insight**：这保证了噪声-目标-控制三元组的配对一致性，避免数据集图像与 teacher 分布不匹配。这个思路可推广到其他条件生成蒸馏任务（如 inpainting、super-resolution），也可作为「保耦合蒸馏」在条件生成场景的具体实现参考。
