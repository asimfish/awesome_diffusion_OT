# FLUX.1 Kontext: Flow Matching for In-Context Image Generation and Editing in Latent Space

> Black Forest Labs et al. · arXiv 2025 · [arXiv](https://arxiv.org/abs/2506.15742) · 证据级 [R] · 课题 T09 Rectified Flow 与轨迹拉直
> **一句话**：12B rectified flow transformer 用序列拼接统一图像生成与编辑，LADD 蒸馏实现 3–5 秒 1024² 生成。

## 1. 问题

FLUX.1 Kontext 要解决的是「统一图像生成与编辑」问题：同一个模型既能做局部编辑（保持周围上下文不变，如换车颜色）、又能做生成式 in-context 任务（提取视觉概念并在新环境中忠实再现），还能在无上下文图像时退化为纯文本生成图像。形式化目标是逼近条件分布 $p(x \mid y, c)$，其中 $x$ 是目标图像，$y$ 是可选上下文图像（可为 $\varnothing$），$c$ 是自然语言指令（Sec. 3, Eq.(1)）。

作者指出现有方法有三个不足（Sec. 1）：(i) 基于合成指令-响应对训练的指令编辑方法继承了其生成管线的缺陷，限制编辑的多样性与真实感；(ii) 多轮编辑中保持角色与物体的准确外观仍是开放问题，阻碍故事叙述与品牌敏感应用；(iii) 集成到多模态大模型中的自回归编辑方法除质量低于去噪方法外，运行时间过长，不适合交互使用。此外，现有编辑基准存在偏差：InstructPix2Pix 依赖合成 Stable Diffusion 样本与 GPT 生成指令，MagicBrush 受限于 DALLE-2 能力，Emu-Edit 使用低分辨率图像且只覆盖编辑任务（Sec. 4.1）。

## 2. 方法

核心思想是**序列拼接**：把上下文图像编码为 latent token 后直接拼接到目标图像 token 序列上，送入同一个 rectified flow transformer，不引入额外适配器或专用分支。作者报告「channel-wise concatenation of x and y was also tested but in initial experiments we found this design choice to perform worse」（Sec. 3），即通道拼接在初步实验中表现更差。

**Token 序列构造**：图像经冻结的 FLUX 自编码器编码为 latent token。位置信息用 3D RoPE，目标 token 位置为 $u_x = (0, h, w)$，第 $i$ 个上下文图像的 token 位置为 $u_{y_i} = (i, h, w)$，$i = 1, \dots, N$（Eq.(2)）。上下文 token 获得一个常数偏移，作为虚拟时间步，将上下文块与目标块干净分离，同时保留各自内部空间结构。

**训练目标**：rectified flow matching 损失
$$L_\theta = \mathbb{E}_{t \sim p(t), x, y, c}\left[\|v_\theta(z_t, t, y, c) - (\varepsilon - x)\|_2^2\right] \tag{Eq.(3)}$$
其中 $z_t = (1-t)x + t\varepsilon$，$\varepsilon \sim \mathcal{N}(0,1)$。时间步采样用 logit-normal shift schedule $p(t; \mu, \sigma=1.0)$，训练时根据数据分辨率调整 mode $\mu$（Sec. 3）。附录 A.2 给出推导：$\alpha$-shift 等价于 logit-normal 分布取 $\mu = \log \alpha$、$\sigma = 1.0$；例如 $\alpha = 3.0$ 对应 $\mu = \log 3.0 = 1.0986$（Appendix A.2, Eq.(9)-(10)）。当 $y = \varnothing$ 时省略所有 $y$ token，保留纯文本生成能力。

**模型架构**：FLUX.1 是 latent space 中的 rectified flow transformer，混合 double stream 与 single stream 块（Sec. 2）。Double stream 块对图像与文本 token 使用独立权重，通过拼接 token 上的注意力操作混合；之后拼接序列并经过 38 个 single stream 块；最后丢弃文本 token，解码图像 token。Single stream 块使用 fused feed-forward 块（受 Dehghani et al. 启发），将调制参数数量减半，并融合注意力输入/输出线性层与 MLP，提高训练与推理效率。自编码器从头训练，带对抗目标，使用 16 个 latent channel（Sec. 2）。

**少步化**：采用 latent adversarial diffusion distillation（LADD）[47,48,49]，减少采样步数并通过对抗训练提升质量（Sec. 3）。FLUX.1 Kontext [pro] 用 flow 目标训练后接 LADD；[dev] 通过 guidance distillation 到 12B diffusion transformer（遵循 Meng et al. 的技术），且 [dev] 只训练 image-to-image 任务，不训练纯文本生成任务（Sec. 3）。

## 4. 实验与数字

**VAE 重建质量**（Table 1，4096 张 ImageNet 图像，256×256）：

| 模型 | PDist ↓ | SSIM ↑ | PSNR ↑ |
|---|---|---|---|
| Flux-VAE | 0.332 ± 0.003 | 0.896 ± 0.004 | 31.1 ± 0.08 |
| SD3-VAE | 0.452 ± 0.004 | 0.858 ± 0.005 | 29.6 ± 0.07 |
| SD3-TAE | 0.746 ± 0.004 | 0.774 ± 0.014 | 27.9 ± 0.06 |
| SDXL-VAE | 0.890 ± 0.005 | 0.748 ± 0.006 | 25.9 ± 0.07 |
| SD-VAE | 0.949 ± 0.005 | 0.720 ± 0.004 | 25.0 ± 0.07 |

**KontextBench**（Sec. 4.1）：1026 个 image-prompt 对，来自 108 张基础图像（个人照片、CC 许可艺术、公有领域图像、AI 生成内容）。五类任务：local instruction editing 416 例、global instruction editing 262 例、text editing 92 例、style reference 63 例、character reference 193 例。

**推理延迟**（Figure 7）：1024×1024 生成的中位延迟，FLUX.1 Kontext 在 text-to-image 与 image-to-image 上均为 3–5 秒（Sec. 1 报告「3–5 seconds」；Figure 7 显示与其他模型对比，作者报告「outperforming related models by up to an order of magnitude in speed difference」，Sec. 4.2）。

**Image-to-image 人类评估**（Figure 8）：FLUX.1 Kontext [max] 和 [pro] 在 local editing、text editing、general CREF 类别中最佳；global editing 中仅次于 gpt-image-1；SREF 中仅次于 Gen-4 References（Sec. 4.2）。AuraFace 相似度（Figure 8f）显示 FLUX.1 Kontext 在面部特征保持上优于所有其他模型。

**Text-to-image 评估**（Figure 9）：在 Internal-T2I-Bench（1000 个测试 prompt，来自 DrawBench、PartiPrompts 与真实用户查询）上分解为五个维度：prompt following、aesthetics、realism、typography accuracy、inference speed。FLUX.1 Kontext 在各类别上表现均衡，且相对前代 FLUX1.1 [pro] 一致提升；从 [pro] 到 [max] 有渐进增益。作者引入术语「bakeyness」描述通用偏好基准偏爱的「AI 美学」特征（过饱和色彩、过度聚焦中心主体、明显 bokeh、风格同质化）。

**多轮一致性**（Figure 12）：用相同起始图像与相同 prompt 序列比较 FLUX.1 Kontext、gpt-image-1、Runway Gen4 的迭代编辑。AuraFace 余弦相似度显示 FLUX.1 Kontext 的角色漂移比竞争方法更慢。作者注明最后一次编辑（"Add sunglasses"）因面部部分遮挡，相似度下降是预期的。

**训练基础设施**（Sec. 3）：FSDP2 混合精度（all-gather 用 bfloat16，gradient reduce-scatter 用 float32）；selective activation checkpointing 降低 VRAM；Flash Attention 3；Transformer 块的 regional compilation。

## 5. 在 OT×扩散地图中的位置

本文是 T09（Rectified Flow 与轨迹拉直）的**工业实践端点**，与课题背景中「工业上 FLUX/SD3.5 训练用 RF 公式，但少步化实际走 LADD 对抗蒸馏路线」的判断完全吻合。具体对应关系：

**继承**：训练目标直接采用 Liu et al. 的 rectified flow 公式（Eq.(3) 即 $v_\theta(z_t,t,y,c) - (\varepsilon - x)$ 形式），时间步采样采用 Esser et al. SD3 的 logit-normal 分布（引用 [12]），并明确写出 $\alpha$-shift 与 logit-normal 参数 $\mu$ 的等价关系（Appendix A.2）。这确认了 SD3 确立的「RF 公式 + logit-normal 时间步采样」工业标准在 FLUX 系列中的延续。

**少步化路线选择**：本文明确选择 LADD 对抗蒸馏而非 reflow 来减少采样步数（Sec. 3：「We tackle both challenges using latent adversarial diffusion distillation (LADD)」）。这为课题背景中「reflow vs 对抗蒸馏的 scaling law」开放问题提供了一个工业侧数据点：在 12B 参数规模、1024×1024 分辨率、统一生成/编辑任务上，作者选择了 LADD。但本文未提供 reflow 与 LADD 的对照实验，因此不能作为「LADD 优于 reflow」的证据，只能作为「工业界在此规模上选择 LADD」的案例。

**理论张力位置**：本文不涉及 reflow 迭代、直线度度量或 OT 最优性讨论。它的贡献在于展示 RF 公式在「多模态条件（图像上下文 + 文本指令）」下的扩展方式——通过序列拼接将上下文图像作为额外 token 输入，而不改变 RF 训练目标本身。这与课题中「RF 公式已成为新一代大模型训练标准」的观察一致，但将 RF 的应用范围从纯 T2I 扩展到统一的 T2I/I2I。

**与 KontextBench 的关系**：本文引入的基准填补了编辑模型评估中「真实世界使用场景」的空白，但其定位是产品评估而非理论检验，不涉及 OT 或轨迹拉直的度量。

## 6. 局限与批评

**作者承认的局限**（Sec. 5）：
1. 过度多轮编辑会引入视觉伪影，降低图像质量（Figure 15 展示六轮迭代后的可见伪影）。
2. 模型偶尔无法准确遵循指令，忽略特定 prompt 要求（Figure 15 中间行：要求「move the coffee to the left」，模型却添加了奶泡而非重新定位杯子）。
3. 蒸馏过程可能引入影响输出保真度的视觉伪影。

**读出来的局限**：
1. **无定量消融**：序列拼接 vs 通道拼接的对比仅一句「initial experiments we found this design choice to perform worse」，未给出数字、实验设置或失败模式分析。作为核心架构决策，证据强度不足。
2. **评估依赖人类偏好与专有 API**：Figure 8 和 Figure 9 的核心结果是人类评估分数，且对比对象包括 gpt-image-1、Gen-4 等专有系统，无法独立复现。AuraFace 相似度是唯一可复现的定量指标，但只覆盖面部保持，不覆盖物体、风格或文本编辑质量。
3. **「bakeyness」概念未操作化**：作者批评现有 T2I 基准偏爱「AI 美学」，但未给出 bakeyness 的可计算定义或度量，Internal-T2I-Bench 的分解维度（aesthetics、realism 等）仍依赖人类判断。
4. **多图像输入未实现**：公式支持 $y_1, \dots, y_N$（Eq.(2)），但作者明确「we focus on single context images for conditioning at this time」（Sec. 3），多图能力仅停留在架构层面。
5. **速度对比的基线不透明**：Figure 7 显示「up to an order of magnitude」的速度优势，但未列出各模型的具体延迟数字或 API 调用条件（是否包含排队、网络延迟等）。

## 7. 对我们的启发

1. **「序列拼接 vs 通道拼接」的对照实验缺口**：本文仅用一句话否定了通道拼接，未给出数字。这对应课题切入点 #2 的方法论精神——关键架构决策需要可复现的对照实验。可以在小规模（如 SD1.5/SDXL 级）上系统比较两种上下文注入方式对编辑质量、角色一致性、训练收敛速度的影响，产出可引用的定量结论。

2. **LADD 蒸馏在「统一生成/编辑」任务上的行为**：本文报告蒸馏可能引入视觉伪影（Sec. 5 局限），且 [dev] 只训练 I2I 任务。这提示蒸馏在「多任务统一模型」上的 trade-off 尚未被系统研究。可设计实验：同一 RF 教师模型分别用 reflow 与 LADD 蒸馏到少步，比较在 T2I 与 I2I 子任务上的质量退化模式——直接回应课题开放问题 #5「reflow vs 对抗蒸馏的 scaling law」，且本文的 [pro]（LADD）与 [dev]（guidance distillation）已暗示两条路线在任务覆盖上的差异。

3. **多轮编辑漂移作为「轨迹拉直」的应用层度量**：本文用 AuraFace 余弦相似度追踪多轮编辑中的角色漂移（Figure 12），这本质上是「条件分布偏移下的采样稳定性」问题。课题中 reflow 的直线度 $S(Z)$ 度量的是单次采样的轨迹弯曲，而多轮编辑漂移可视为「迭代条件采样」的累积误差。将两者联系起来——例如研究 RF 模型的轨迹直线度是否预测多轮编辑的漂移速率——可能是一个新的理论-应用连接点。
