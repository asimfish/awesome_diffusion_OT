# LTX-Video: Realtime Video Latent Diffusion

> Yoav HaCohen et al. · arXiv 2024 · [arXiv](https://arxiv.org/abs/2501.00103) · 证据级 [R] · 课题 T19 视频生成与时序一致性中的 OT/流
> **一句话**：1:192 高压缩 Video-VAE + rectified flow 协同设计，H100 上 2 秒生成 5 秒 768×512·24fps 视频。

## 1. 问题

视频扩散模型的推理成本随帧数线性增长，而 transformer 的注意力操作对 token 数呈二次方复杂度（Sec. 2.1）。此前方法（CogVideoX、MovieGen、PyramidFlow、Open-Sora Plan、HunyuanVideo）采用 8×8×4 或 8×8×8 的 VAE 时空压缩，输出 16 通道，总压缩比 1:48 或 1:96；随后在 transformer 输入端用 2×2×1 的 patchifier 收集 latent patch，达到 1:1024 或 1:2048 的 pixels-to-tokens 比（Table 1）。这些模型把 Video-VAE 和去噪 transformer 当作独立组件分别设计，VAE 的压缩率没有针对 transformer 的 token 效率做联合优化。

高压缩率带来一个直接矛盾：latent 空间无法保留全部高频细节，解码到像素空间时产生伪影。Sora 和 MovieGen 的解法是加一个第二阶段上采样扩散模型，但这引入额外计算和运行时间成本（Sec. 2.1.1）。LTX-Video 要解决的问题是：在不增加上采样模块的前提下，把压缩率推到 1:192（pixels-to-tokens 比 1:8192，是典型配置的 4 倍），同时保持视觉质量、运动保真度和 prompt 遵循度，并实现快于实时播放的生成速度。

## 2. 方法

核心思想是「整体式 latent diffusion」：把 patchifying 操作从 transformer 输入端移到 VAE 编码器输入端，让 VAE 直接输出 32×32×8 时空压缩、128 通道的 latent（总压缩 1:192，无需 patchifier）；同时让 VAE 解码器承担最后一步去噪任务，在像素空间直接输出干净结果（Fig. 2）。

**Video-VAE 设计**（Sec. 2.1）：

- **共享扩散目标**（Sec. 2.1.1）：rectified-flow 模型映射噪声 latent $z_{t_i} = (1-t_i)z_0 + t_i\epsilon$ 到干净 latent $z_0$。由于迭代次数有限，$z_0$ 存在残差不确定性，在高压缩率下表现为解码伪影。作者把解码器训练为扩散模型：$x_0 = D(z_{t_i}, t_i) = D((1-t_i)z_0 + t_i\epsilon, t_i)$，在噪声水平 $[0, 0.2]$ 范围内训练，执行最后一步 latent-to-pixel 去噪。因为 $D$ 映射不同维度空间，不能迭代使用，但可以执行 base model 无法完成的最后一步。
- **Reconstruction GAN（rGAN）**（Sec. 2.1.2）：传统 GAN 判别器只看到真实或重建样本之一，难以判断模糊 patch 是景深效果还是伪影。rGAN 把输入和重建样本拼接后交给判别器，让其判断哪个是原始、哪个是重建。作者报告这大幅提升 GAN 稳定性和性能。
- **多层噪声注入**（Sec. 2.1.3）：遵循 StyleGAN，在 VAE 解码器多个层注入噪声，噪声水平逐通道学习。
- **均匀 log-variance**（Sec. 2.1.4）：宽 latent 空间（128 通道）下标准 KL loss 导致部分通道被「牺牲」给 KL 项（均值趋零、方差趋一）。改用所有通道共享单一预测 logvar，均匀分布 KL loss 的影响。
- **Video DWT Loss**（Sec. 2.1.5）：对输入和重建视频各计算 8 个 3D 离散小波变换，用 L1 距离作为损失，弥补 L1/L2 像素损失对高频细节的不足。
- 最终 VAE 损失组合：像素重建（MSE）、Video-DWT（L1）、感知损失（LPIPS）、Reconstruction-GAN（Sec. 2.1.6）。采用因果 VAE（3D 因果卷积），第一帧作为单独 latent frame 编码（Fig. 4a）。

**Video Transformer**（Sec. 2.2）：基于 Pixart-α 架构，28 个 transformer block，hidden dimension 2048，FFN factor 4，Self + Cross attention（Table 1）。关键修改：

- **RoPE 位置编码**（Sec. 2.2.1）：用归一化分数坐标的 RoPE 替代绝对位置嵌入。空间和时间坐标分别以像素和秒为单位计算，相对于预定义最大分辨率和时长归一化。时间嵌入纳入原始 FPS。RoPE 频率采用指数递增间隔（Fig. 8），而非开源实现常用的逆指数间隔。
- **QK 归一化**（Sec. 2.2.2）：在点积注意力前对 query 和 key 施加 RMSNorm，避免注意力 logits 过大导致注意力权重近零熵。

**图像条件**（Sec. 2.4）：基于 Open-Sora 的 timestep 条件机制，允许每个 token 有不同的 timestep 和噪声水平。训练时偶尔把第一帧 token 的 timestep 设为小随机值；推理时条件图像经因果 VAE 编码为时间维度 1 的 latent tensor，与随机噪声 latent 拼接，条件 token 的 timestep 设为小值 $t_c$，其余 token 设为 $t=1$（Fig. 9）。

**Rectified-Flow 训练**（Sec. 2.5）：前向过程 $z_t = (1-t)z_0 + t\epsilon$，模型预测速度 $v = \epsilon - z_0$。timestep 采样从 log-normal 分布，根据 token 数向高噪声区域偏移，pdf 在百分位 0.5 和 99.9 处截断（Fig. 10）。多分辨率训练中所有输入样本保持近似相同 token 数，用 0%–20% 的随机 token dropping 固定序列长度（Sec. 2.5.3）。图像作为分辨率-时长组合之一与视频同时训练（Sec. 2.5.4）。

## 4. 实验与数字

**模型规格对比**（Table 1）：

| 模型 | Base model size | VAE 时空压缩 | VAE 输出通道 | VAE 总压缩 | Transformer patchifier | Tokens-to-pixels | Transformer blocks |
|---|---|---|---|---|---|---|---|
| MovieGen | 30B | 8×8×8 | 16 | 1:96 | 2×2×1 | 1:2048 | 48 |
| HunyuanVideo | 13B | 8×8×4 | 16 | 1:48 | 2×2×1 | 1:1024 | 60 |
| PyramidFlow | 2B | 8×8×8 | 16 | 1:96 | 2×2×1 | 1:2048 | 24 |
| CogVideoX | 2B/5B | 8×8×4 | 16 | 1:48 | 2×2×1 | 1:1024 | 30/42 |
| LTX-Video | 1.9B | 32×32×8 | 128 | 1:192 | 1×1×1 | 1:8192 | 28 |

**生成速度**：5 秒 24fps 视频（121 帧）768×512 分辨率，20 步扩散，Nvidia H100 上 2 秒生成（Abstract；Sec. 1）。作者报告这是「快于实时播放」——生成时间短于观看时间。

**人类评估**（Sec. 4.2，Table 2）：1,000 个 text-to-video prompt 和 1,000 个 image-to-video 对（图像用 FLUX.1 生成），5 秒 768×512 视频，40 步扩散，20 名参与者，两两比较，胜率 = wins/(wins+losses)：

| 模型 | Text-to-video 胜率 | Image-to-video 胜率 |
|---|---|---|
| Open-Sora Plan | 20% | 20% |
| CogVideoX 2B | 38% | 47% |
| PyramidFlow | 51% | 35% |
| LTX-Video | 85% | 91% |

两两胜率矩阵见 Fig. 15。两组各 10 名参与者的胜率差异小于 2%（Sec. 4.2）。

**消融**：

- rGAN vs 传统 GAN（Sec. 4.3.1）：在 1:192 压缩率下，传统重建+GAN 损失组合无法一致重建原始视频，rGAN 显著减少可见伪影（Fig. 16）。
- RoPE 频率间隔（Sec. 4.3.2）：指数间隔的训练 loss 始终低于逆指数间隔（Fig. 17）。
- 去噪 VAE 解码器（Sec. 4.4）：内部用户研究比较 timestep $t=0.05$（执行去噪）与 $t=0.0$（不执行去噪）的解码器，前者被强烈偏好，高运动视频中改善尤为明显。

**Latent 冗余分析**（Sec. 2.1，Fig. 3）：对 128 个视频样本的 latent 像素做 PCA，训练初期（4% 步数）通道间自相关矩阵有高非对角值，训练完成时接近零；累计解释方差曲线显示训练后期各通道贡献更均匀。

## 5. 在 OT×扩散地图中的位置

LTX-Video 属于「实时工程线」：高压缩 VAE + rectified flow 训练，把视频生成从分钟级推进到秒级。它与课题背景中提到的 HunyuanVideo、Wan、Pyramid-Flow 同属 Sora 后开源阵营全面转向流公式（FM/RF）的实践者——LTX-Video 明确采用 rectified flow（Sec. 2.5.1，引用 [36] 和 SD3 [12]），预测速度 $v = \epsilon - z_0$。

在 OT×扩散的理论张力中，LTX-Video 不直接处理最优传输的几何约束或帧间噪声耦合问题。它的贡献集中在推理管线的「每步成本」轴：通过 1:192 压缩把 token 数压到典型配置的 1/4，使 transformer 能在高压缩 latent 空间上做全时空自注意力。这与课题背景中「把每步成本压低（高压缩 VAE、缓存、稀疏注意力、流式缓冲）」的加速轴直接对应。

与蒸馏线（DMD/VDOT/一致性）的关系：LTX-Video 是 2B 参数、20 步、未蒸馏的模型（Sec. 1 明确写「before distillation」）。它代表的是「未蒸馏的实时基线」——后续蒸馏工作（如 VDOT 用 OT 距离蒸 VACE-Wan-14B 到 4 步）可以以此为参照，检验在更高压缩 latent 空间上蒸馏的可行性与运动退化问题。LTX-Video 的「VAE 解码器承担最后一步去噪」设计也值得注意：它把去噪轨迹的末端从 latent 空间移到像素空间，这在蒸馏场景下意味着教师模型的最后一步本身就是跨空间映射，对「保耦合蒸馏」的轨迹一致性提出了额外约束。

## 6. 局限与批评

作者承认的局限（Sec. 5）：

1. **对 prompt 表述敏感**：模糊或不清晰的 prompt 可能导致输出不连贯。
2. **长视频支持有限**：目前只支持最多 10 秒的短视频，更长时长的时序一致性和 prompt 保真度是开放问题。
3. **领域泛化未充分测试**：多视角合成、细粒度编辑等专门任务未经过广泛评估。

读出来的局限：

1. **评估仅限人类偏好**：没有报告 FVD、CLIP score 等自动指标，无法与后续工作做定量对比。人类评估的 20 名参与者规模较小，且只与「相似规模」模型比较，未与更大模型（如 HunyuanVideo 13B）对比质量。
2. **「快于实时」的硬件条件**：2 秒生成 5 秒视频是在 Nvidia H100 上测得（Abstract），消费级 GPU 上的实际速度未给出数字。Sec. 6 声称「可在消费级 GPU 上运行」，但未提供具体硬件和延迟数据。
3. **VAE 解码器去噪的噪声范围**：解码器只在 $[0, 0.2]$ 噪声水平训练（Sec. 2.1.1），这意味着 base model 必须在 latent 空间把噪声降到该范围内，解码器才能有效工作。如果 base model 的残差噪声超出 0.2，解码器的行为未被训练覆盖——这是一个隐含的分布外风险。
4. **训练数据细节缺失**：数据规模、训练步数、batch size、学习率等关键训练超参数均未报告（Sec. 4.1 只有一句话），复现性受限。

## 7. 对我们的启发

1. **高压缩 latent 空间上的 OT 蒸馏可行性**：LTX-Video 证明 1:192 压缩下 20 步 RF 可生成可接受质量的视频。一个直接问题是：在 128 通道、32×32×8 压缩的 latent 空间上，OT-DMD 或一致性蒸馏是否仍能保持运动幅度？高压缩可能加剧少步蒸馏的「运动塌缩」——因为 latent 空间本身已丢失高频运动细节，蒸馏进一步压缩轨迹时，运动信息的损失可能被放大。可设计实验：固定 LTX-Video 教师，对照 KL-DMD / OT-DMD / 对抗三种目标蒸到 4 步，用光流幅度分布的 Wasserstein 距离量化运动退化（对应切入点 #2）。
2. **「解码器即最后一步去噪」对蒸馏的启示**：LTX-Video 把去噪轨迹末端从 latent 空间移到像素空间，这意味着教师模型的「最后一步」是跨空间映射 $D(z_{t_1}, t_1)$。在保耦合蒸馏中，学生的最后一步是否也应保留这种跨空间结构？如果学生完全在 latent 空间去噪再解码，可能丢失教师最后一步在像素空间注入的高频细节。这为「保耦合蒸馏」提供了一个新的设计维度：蒸馏目标函数是否需要对最后一步的跨空间映射做特殊处理（对应切入点 #3）。
3. **token 级 timestep 条件作为帧间耦合的工程接口**：LTX-Video 的 per-token timestep 机制（Sec. 2.4）允许不同 token 处于不同噪声水平。这为帧间噪声耦合提供了一个现成的工程接口：可以把相邻帧的噪声场视为需「分布保持地传输」的对象，通过给不同帧的 token 设置不同的 timestep 和噪声水平来实现 HIWYN 式的噪声平流，而不需要修改模型架构。在 LTX-Video 的 latent 空间（128 通道）上做 Sinkhorn 帧间耦合的代价比像素空间低得多，值得尝试（对应切入点 #1）。
